## 在这台电脑启动

双击 **启动系统.cmd**，等待终端显示服务器就绪，然后浏览器访问 **http://127.0.0.1:8765/**。服务在后台持续运行，关闭启动窗口不会停止；需要停止时运行 **stop.ps1**。重复启动会复用已运行的服务。服务器仅绑定本机，不对局域网或公网开放。

演示账号密码已随机生成，见 **data/demo-accounts.txt**：

- `admin`：管理员，查看所有订单、录入及分摊财务、创建业务员、锁定归档。
- `alice`：林晓，只能查看和操作自己订单的非财务部分。
- `bob`：陈宇，只能查看和操作自己订单的非财务部分。

密码不写进源代码，演示命令再次执行不会重置账号或覆盖数据。正式使用前请创建独立管理员和业务员、停用演示账号；目前账号停用和管理员创建通过 Django shell/命令行操作。

## 建议试用顺序

1. 用 admin 登录看仪表盘。所有客户和物流资料均为虚构数据。
2. 打开 DEMO-2026-001：查看 A/B/C、第二次 B 补单及 D 产品，D 有一笔待分配收款。
3. 新建发货，输入 A 1000、B 800、C 900；计算预览，检查本批待收待付。
4. 若确认实际发货，会正式扣减剩余数量并固化占款。演示订单已包含一批历史发货。
5. 查看财务流水，点击“分摊”，选择小项、结算汇率和批次。已有发货欠款时必须先选择欠款批次。
6. 用 alice 和 bob 分别登录，检查各自可见数据。直接访问别人的订单 URL 返回 404。
7. DEMO-2026-003 已全部结清，可下载三表或测试“锁定并归档”。

## 限制及后续阶段

本版本用于本机业务规则验证，**尚未做生产部署与安全验收**。

- 生产目标 PostgreSQL，当前预览使用 SQLite。事务行锁代码已写，真实 PostgreSQL 并发竞争仍须验收；未实现数据库 RLS。
- 业务员目前不能提交财务待审申请，财务录入由管理员直接操作。
- 历史记录不提供直接修改/删除。退款、冲销、退货、折让、超收款结转、手续费、订单更正和物流后补维护未实现。
- 付款条款为文本；未实现到期日、分期账期自动计算。本批“待收/待付”是尚未覆盖金额。
- 预览不预占；无持久化发货草稿。并行操作以最终确认时余额为准。
- 实际货代运费单独记录，未纳入供应商产品款结清比例，归档前须人工核对。
- 凭证默认位于 data/private/；服务器方案使用私有持久卷、HTTPS及Redis共享限流，并提供备份恢复工具。磁盘/异机备份加密、病毒扫描、MFA/账户恢复和细化运维权限仍需按生产环境配置验收。
- 没有启用任何销毁入口，也没有上传任何业务数据到云端。销毁须在归档核验和备份生命周期验收后单独实现。
- 尚无原有 Excel 批量导入、多公司账套、单个订单中同一小项多供应商拆采购、账号转交界面。

## 运行与开发

Python 3.10+。依赖见 requirements.txt。首次运行启动脚本会查找项目 venv、当前工作区已安装环境或创建项目 .venv。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py test tracker
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8765 --noreload --insecure
```

`--insecure` 仅让 Django 开发服务器在 DEBUG 关闭时提供本机 CSS/JS，不会公开凭证。它不能代替正式部署服务器。

不需要演示数据时跳过 seed_demo，用 `python manage.py createsuperuser` 创建管理员。数据库和本地密钥默认位于 data/，通过 DATA_DIR 环境变量更改。不要把该目录提交到版本库或发送给他人。

## PostgreSQL 部署准备

优先按 [服务器部署.md](服务器部署.md) 使用现成 Compose 配置；`DJANGO_ENV=production` 会强制校验密钥、域名、PostgreSQL和Redis配置，避免误用 SQLite。生产启动不会运行 seed_demo。

设置 POSTGRES_DB、POSTGRES_USER、POSTGRES_PASSWORD、POSTGRES_HOST、POSTGRES_PORT；设置 DJANGO_SECRET_KEY、DJANGO_ALLOWED_HOSTS 和 HTTPS_ONLY=1。生产环境使用正式 WSGI 服务器和 HTTPS 反向代理，静态资源通过 collectstatic 提供，附件始终走授权下载。数据库账号使用最小权限，不能作为超级用户运行。不要把当前开发服务器绑定公网。

所有生产数据库升级、导入、备份、归档销毁需要在独立测试环境验收后进行。具体核算口径见 BUSINESS_RULES.md。
